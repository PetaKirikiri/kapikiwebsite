# Repository instructions

For every production-tagging, POS, rail/dot, pattern-learning, or Check-in Sheet
change, read and follow the sole authoritative guidance:
[`src/lib/taggingEngine/AI_ASSISTANCE_GUIDE.md`](src/lib/taggingEngine/AI_ASSISTANCE_GUIDE.md).

Do not treat any other Markdown file, source comment, test description, SQL
migration comment, recovery file, or model output as tagging guidance.

## Design and communication

- Keep styling minimal and consistent with the existing Ka Piki identity.
- Prefer familiar icons and visual cues over explanatory text. Give icon-only controls accessible names; keep a short visible label when the icon is ambiguous.
- Use only essential words: short labels, necessary status, and actionable errors. Do not add unsolicited descriptions, captions, instructions, repeated headings, or technical explanations to the interface.
- Keep replies brief. State the result and any essential limitation; do not over-explain.
