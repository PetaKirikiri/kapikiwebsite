# Individual account setup

`account-setup.html#token=…` uses the same form as the visual preview, backed by the recipient's saved registration. The server determines their email and registered levels. Multiple registrations require an explicit choice. The page has no analytics and does not consume the Supabase Auth token until the learner submits their form. Passwords go only to Auth. `007_account_invitations.sql` stores a SHA-256 digest, expiry and completion state, verifies account ownership, updates the original details, and records the confirmed level without deleting registration history or granting permissions.

Run `node scripts/setup-account-invitations.mjs` for rollback-only database checks; `--install` applies the migration. `npx tsx scripts/prepare-account-invitations.ts` audits the October MOE audience without changes. Preparing requires the server-only `STUDENT_SUPABASE_SECRET_KEY` and the actual deployed `account-setup.html` page at `KA_PIKI_SITE_URL`. Then `--prepare` generates one Supabase invitation per distinct email and writes one recipient-specific, unsent draft per invitation under ignored `.local/account-invitations/` (private file permissions). No mail is sent by this script. Never commit or print these files: the links are credentials.

Generate links immediately before an approved send, not while reviewing copy. Application expiry is one hour, capped by the provider's configured OTP expiry; regenerate expired drafts. Reissuing revokes the older application link. Invalid, expired, revoked and completed links cannot expose details or complete setup. Each draft includes its expiry and an invitation ID for delivery tracking; the sender must address only its `to` recipient and record delivery separately. The email asks everyone to “check your details, add anything missing, and set your password.” A live provider-token/password test and deployed page check are required before sending the announcement.
